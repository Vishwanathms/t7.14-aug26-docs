# Level 4 — Separate Business Logic

At this point our server contains:

```text
HTTP handling
+
Routing
+
Student searching
+
Validation
+
Response generation
```

This becomes difficult to test.

We should separate **business logic** from HTTP logic.

Create:

```text
student-service.js
```

Project:

```text
student-portal-api/
├── package.json
├── server.js
└── student-service.js
```

---

# Level 4.1 — Create Student Service

Add:

```javascript
const students = [
    {
        id: 1,
        name: 'Aditi',
        course: 'Java'
    },
    {
        id: 2,
        name: 'Rahul',
        course: 'Node.js'
    },
    {
        id: 3,
        name: 'Priya',
        course: 'Spring Boot'
    }
];

function getAllStudents() {
    return students;
}

function getStudentById(id) {
    return students.find(
        student => student.id === id
    );
}

module.exports = {
    getAllStudents,
    getStudentById
};
```

---

# Level 4.2 — Use the Service

At the top of `server.js`:

```javascript
const http = require('http');

const {
    getAllStudents,
    getStudentById
} = require('./student-service');
```

Remove the local student array from `server.js`.

For `/students`:

```javascript
const students = getAllStudents();

res.writeHead(200, {
    'Content-Type': 'application/json'
});

res.end(
    JSON.stringify(students)
);
```

For `/students/:id`:

```javascript
const student =
    getStudentById(studentId);
```

---

# Why Did We Do This?

We now have:

```text
HTTP Layer
   |
   v
server.js
   |
   v
Business Layer
   |
   v
student-service.js
```

This separation makes the business logic easy to test.

We can test:

```javascript
getStudentById(1)
```

without starting the HTTP server.

This is a very important backend development principle.
