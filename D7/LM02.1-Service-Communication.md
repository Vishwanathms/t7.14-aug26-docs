# Lab Manual — Service-to-Service Communication Using Spring Boot RestClient

# Service Communication Using REST and Spring Boot RestClient

## Module

**Service Communication — Microservices**

## Duration

**30–35 minutes hands-on**

## Difficulty

Beginner / Fresher

## Technology

* Java
* Spring Boot
* Maven
* REST
* HTTP
* JSON
* Spring `RestClient`
* IntelliJ IDEA

---

# 1. Lab Objective

In this lab, you will build two independent Spring Boot applications:

```text
Student Service
      |
      | REST / HTTP
      ↓
Course Service
```

The Student Service will call the Course Service using Spring Boot's `RestClient`.

By the end of the lab, you will be able to:

1. Create two independent Spring Boot applications.
2. Run two Spring Boot applications on different ports.
3. Create a REST API in the Course Service.
4. Test the REST API independently.
5. Create a REST API in the Student Service.
6. Configure `RestClient`.
7. Call one Spring Boot service from another.
8. Receive JSON from the Course Service.
9. Convert the JSON response into a Java object.
10. Combine data from two services.
11. Observe what happens when the downstream service is unavailable.

# 2. Final Architecture

At the end of the lab, you will have:

```text
                         HTTP
                  GET /courses/10
                        │
                        ▼
┌──────────────────┐         ┌──────────────────┐
│ Student Service  │────────►│  Course Service  │
│                  │         │                  │
│ Port: 8080       │         │ Port: 8081       │
└────────┬─────────┘         └──────────────────┘
         │
         │
         ▼
      Client
```

The client will call:

```text
GET http://localhost:8080/students/101
```

The Student Service will internally call:

```text
GET http://localhost:8081/courses/10
```

The final response will look like:

```json
{
  "studentId": 101,
  "studentName": "Rahul",
  "course": {
    "id": 10,
    "name": "Spring Boot",
    "duration": 40
  }
}
```

# 4. Important Concept Before Starting

We are going to create **two separate applications**.

## Application 1

```text
course-service
```

This application owns course information.

It will run on:

```text
8081
```

## Application 2

```text
student-service
```

This application owns student information.

It will run on:

```text
8080
```

The Student Service will **not directly access Course Service's data**.

Instead, it will use:

```text
REST API
```

to communicate with the Course Service.
